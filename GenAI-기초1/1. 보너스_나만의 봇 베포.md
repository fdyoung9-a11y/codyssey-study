# 보너스 과제: 나만의 봇 배포

## 1. 배포 목적

최종 프롬프트를 반복적으로 재사용할 수 있는 형태로 배포하기 위해 ChatGPT의 GPTs 기능을 활용하였다. 매번 동일한 시스템 프롬프트를 다시 입력하지 않아도 같은 기준으로 기관장 보고용 회의록을 생성할 수 있도록 전용 봇을 제작하였다.

## 2. GPT 기본 설정

| 항목 | 설정 내용 |
|---|---|
| GPT 이름 | 기관장 보고용 회의록 요약 봇 |
| 활용 기능 | ChatGPT GPTs |
| 주요 용도 | 회의 원문을 기관장 보고용 형식으로 요약 |
| 프롬프트 적용 위치 | Instructions 영역 |
| 배포 방식 | 링크를 통한 재사용 |

## 3. Instructions 설정

GPT의 Instructions 영역에는 최종 시스템 프롬프트를 입력하였다. 이 프롬프트는 회의 원문을 바탕으로 확정된 정보와 제안된 정보를 구분하고, 정해진 출력 형식에 따라 회의록을 생성하도록 설계하였다.

## 4. 주요 출력 항목

사용자가 회의 원문을 입력하면 다음 항목을 정해진 형식으로 출력하도록 구성하였다.

1. 핵심 요약
2. 주요 논의 내용
3. 결정사항
4. 제안사항
5. Action Items
6. 확인 필요 사항
7. 핵심 근거

## 5. 핵심 운영 규칙

봇에는 다음과 같은 환각 방지 및 검증 규칙을 적용하였다.

- 회의 원문이나 사용자의 명시적 추가 정보에 없는 담당자, 날짜, 금액, 장소를 임의로 생성하지 않는다.
- 제안된 내용과 최종 결정된 내용을 명확히 구분한다.
- 확정되지 않은 정보는 `확인 필요`로 표시한다.
- 업무 상태가 원문에 명시되지 않은 경우 `진행 중`, `대기`, `예정`, `완료` 등을 임의로 작성하지 않는다.
- 업무 상태가 확인되지 않은 경우 반드시 `확인 필요`로 표시한다.
- 개인 실명은 역할명으로 바꾸어 작성한다.
- 핵심 근거는 회의 원문이나 사용자의 명시적 추가 정보에서 확인 가능한 내용만 사용한다.

## 6. 활용 효과

GPTs를 활용해 최종 프롬프트를 봇 형태로 배포함으로써 사용자는 매번 긴 프롬프트를 다시 입력할 필요 없이 회의 원문만 제공하면 동일한 기준의 회의록을 반복적으로 생성할 수 있게 되었다.

또한 정해진 출력 구조와 환각 방지 규칙을 지속적으로 적용할 수 있어 다음과 같은 효과를 기대할 수 있다.

- 회의록 작성 시간 단축
- 출력 형식의 일관성 확보
- 제안사항과 결정사항의 혼동 방지
- 담당자·기한·금액·상태의 임의 생성 방지
- 기관장 보고용 문서의 재사용성과 업무 활용성 향상

본 보너스 과제에서는 회의록 자동 작성용 최종 프롬프트를 GPTs의 Instructions 영역에 적용하여 재사용 가능한 전용 봇으로 배포하였다. 이를 통해 사용자는 회의 원문만 입력해도 기관장 보고용 회의록을 동일한 기준으로 생성할 수 있으며, 근거 없는 정보 생성 방지와 미확정 정보 표시 규칙을 반복적으로 적용할 수 있게 되었다.
